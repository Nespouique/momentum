# Story 2.11: Ad-hoc Workout Sessions

## Status: Completed

## Story

**As a** user arriving at the gym without a workout plan,
**I want** to start an ad-hoc session from one exercise and choose what comes next,
**so that** I can train freely without creating a reusable workout first.

## Acceptance Criteria

1. The workouts page offers an “À la volée” entry when no session is active.
2. The user selects a first exercise, then chooses the number of sets and reps before starting the session.
3. The set/rep form is prefilled from the latest completed performance when available, otherwise 3 sets of 10. Weights are taken from that history (0 kg otherwise).
4. After the last set of each exercise, the user can add another exercise or finish the session directly from the rest screen shown after that set (no need to wait for the timer). When the rest ends, the add-or-finish decision screen is shown.
5. Adding an exercise (selection, then sets/reps choice) resumes the standard exercise flow without losing recorded results.
6. The same exercise cannot be added twice in the MVP.
7. Ad-hoc sessions appear in active state, history, calendar, details and exercise statistics.
8. Ad-hoc sessions are stored without a workout and labelled “À la volée”.
9. Template progression acceptance and AI coaching are not offered because no workout template exists.
10. Reloading after an exercise restores the add-or-finish decision.

## Implementation Notes

- `WorkoutSession.type` distinguishes `planned` and `ad_hoc`.
- `WorkoutSession.workoutId` is nullable; consumers must handle a null workout.
- Dynamic `SessionExercise` rows deliberately have no `workoutItem` references.
- `POST /sessions/ad-hoc` and `POST /sessions/:id/exercises` accept optional `sets` (1–10) and `reps` (1–100).
- Rework: the first release created targets automatically and the add-or-finish choice only appeared after the last-set rest timer, while the rest screen said "séance terminée !" with no action.
