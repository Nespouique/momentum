# Story 2.10: Exercise Statistics & Progress Charts

## Status: Completed

## Story

**As a** user,
**I want** to see progress charts and key stats for each exercise I've practiced,
**so that** I can visualize my strength and volume evolution over time and stay motivated.

## Context

L'application permet déjà de voir l'évolution des mensurations via des graphiques (page `profile/measurements/graphs`). Cette story ajoute une page similaire dédiée aux exercices, en réutilisant le même pattern UI (sélecteur en chips, graphique ligne, sélecteur de période, carte de tendance).

Les métriques retenues après consultation auprès de pratiquants :

- **E1RM (Force estimée)** : `poids × (1 + reps/30)` — capte les micro-progressions même quand le poids max stagne
- **Volume total** : `Σ(poids × reps)` par séance — mesure le travail global, pertinent pour l'hypertrophie

La fréquence n'est pas restituée comme courbe (les points du graphique la montrent naturellement) mais comme information textuelle résumée.

### Référence UI : Page mensurations (graphiques)

La page `profile/measurements/graphs` utilise :

- **Chips en grille 3 colonnes** pour sélectionner une mensuration → ici, sélectionner un exercice
- **Carte graphique** avec `LineChart` (Recharts), `ChartContainer`, `ChartTooltip`
- **Sélecteur de période** : 1m, 3m, 6m, 1an, Tout (composants `Button` variant ghost/secondary)
- **TrendCard** : affiche première valeur → dernière valeur, delta absolu et %, icône tendance

On réutilise exactement ces composants et patterns.

## Acceptance Criteria

### AC1 — Accès aux statistiques d'exercices

1. Dans le header de la page `/exercises`, un bouton icône (BarChart3 ou TrendingUp) navigue vers `/exercises/stats`
2. La page `/exercises/stats` affiche le titre "Évolution" avec bouton retour (même pattern que la page mensurations/graphs)

### AC2 — Filtre par groupe musculaire

3. Au-dessus de la grille d'exercices, afficher une barre de filtres par groupe musculaire (scroll horizontal), identique à celle de la page `/exercises` :
   - Chips : "Abdos", "Biceps", "Dos", "Épaules", "Fessiers", "Jambes", "Mollets", "Pectoraux", "Triceps", etc.
   - Seuls les groupes musculaires des exercices pratiqués sont affichés
   - Par défaut aucun filtre actif → tous les exercices pratiqués sont listés
   - Un filtre actif réduit la grille aux exercices de ce groupe musculaire
   - Réutiliser le même composant/pattern de filtres que la page `/exercises`
4. Optionnel : une barre de recherche au-dessus des filtres (identique à `/exercises`) si le nombre d'exercices reste important

### AC3 — Sélecteur d'exercice (chips)

5. Afficher en grille (3 colonnes max, responsive 2 colonnes sur petit écran) les exercices pratiqués, filtrés par le groupe musculaire sélectionné (ou tous si aucun filtre)
6. Les exercices sont triés par ordre alphabétique
7. L'exercice sélectionné utilise `variant="default"` (fond plein), les autres `variant="outline"`
8. Le premier exercice de la liste filtrée est sélectionné par défaut au chargement
9. Quand on change de filtre musculaire, le premier exercice du résultat filtré est automatiquement sélectionné

### AC4 — Toggle de métrique

10. Sous le sélecteur d'exercice, deux boutons toggle : **"Force (E1RM)"** et **"Volume"**
11. Le toggle sélectionné utilise `variant="secondary"`, l'autre `variant="ghost"`
12. Le graphique et la carte tendance se mettent à jour au changement de métrique

### AC5 — Graphique de progression

13. Carte graphique avec :
    - **Titre** : nom de l'exercice sélectionné
    - **Unité** : "kg" pour E1RM, "kg" pour Volume
    - **LineChart** (Recharts) avec la même config que les mensurations :
      - Ligne couleur `accent-orange`
      - Points visibles sur la courbe
      - Grille CartesianGrid en pointillés
      - XAxis : dates formatées (ex: "28 avr.", "16 juin")
      - YAxis : valeurs avec calcul automatique du domaine
14. Chaque point représente une séance où l'exercice a été fait :
    - **E1RM** : le meilleur E1RM parmi toutes les séries de cette séance (`max(poids × (1 + reps/30))`)
    - **Volume** : la somme `Σ(actualWeight × actualReps)` sur toutes les séries complétées de cette séance
15. Si une seule donnée, afficher un point unique (pas de ligne)
16. Si aucune donnée sur la période, afficher un message "Aucune donnée sur cette période"

### AC6 — Sélecteur de période

17. Rangée de boutons sous le graphique : **1m**, **3m**, **6m**, **1an**, **Tout**
18. Même pattern que les mensurations : `Button size="sm"`, sélectionné = `variant="secondary"`, non sélectionné = `variant="ghost"`
19. Période par défaut : **Tout**
20. Le changement de période filtre les données du graphique, de la carte tendance et des infos résumées

### AC7 — Carte de tendance (TrendCard)

21. Sous le sélecteur de période, une carte affichant :
    - Première valeur → **Dernière valeur** (en gras) + unité
    - Delta absolu et pourcentage avec icône tendance (TrendingUp vert / TrendingDown rouge / Minus gris)
    - Même composant `TrendCard` que les mensurations
22. Les valeurs correspondent à la métrique sélectionnée (E1RM ou Volume) sur la période sélectionnée

### AC8 — Informations résumées de l'exercice

23. Sous la carte tendance, une section d'informations contextuelles :
    - **Fréquence** : "X fois (Yx/mois)" sur la période sélectionnée
      - X = nombre total de séances avec cet exercice sur la période
      - Y = moyenne par mois arrondie à 1 décimale (ex: "3.2x/mois")
    - **Poids max sur la période** : "Poids max : Xkg (sur Y reps le DD/MM/YYYY)"
      - X = la charge la plus lourde effectivement soulevée (parmi `actualWeight`)
      - Y = le nombre de reps réalisées sur cette série
      - Date de la séance correspondante
24. Si la période ne contient qu'une séance, la fréquence affiche "1 fois"

### Comportement du toggle métrique

| Métrique     | Valeur par point                              | Unité | Description tooltip    |
| ------------ | --------------------------------------------- | ----- | ---------------------- |
| Force (E1RM) | `max(poids × (1 + reps/30))` parmi les séries | kg    | "Force estimée (E1RM)" |
| Volume       | `Σ(poids × reps)` toutes séries               | kg    | "Volume total"         |

### Calcul E1RM — Formule d'Epley

```
E1RM = poids × (1 + reps / 30)
```

Pour chaque séance, on prend le **meilleur E1RM** parmi toutes les séries complétées de l'exercice :

```
e1rm_seance = max(serie.actualWeight × (1 + serie.actualReps / 30)) pour chaque série
```

### Calcul Volume total

```
volume_seance = Σ(serie.actualWeight × serie.actualReps) pour chaque série complétée
```

Séries sans `actualWeight` ou `actualReps` (null) sont exclues du calcul.

## Technical Notes

### Données nécessaires — Nouvel endpoint API

**GET `/exercises/stats`** — Données de tous les exercices pratiqués par l'utilisateur

Retourne la liste des exercices avec les données de séances pour le graphique.

```typescript
interface ExerciseStatsResponse {
  exercises: PracticedExercise[];
}

interface PracticedExercise {
  exerciseId: string;
  exerciseName: string;
  /** Données par séance, triées par date croissante */
  sessions: ExerciseSessionData[];
}

interface ExerciseSessionData {
  sessionId: string;
  completedAt: string; // ISO date
  /** Meilleur E1RM parmi les séries : max(weight × (1 + reps/30)) */
  bestE1RM: number;
  /** Volume total : Σ(weight × reps) */
  totalVolume: number;
  /** Poids max soulevé dans cette séance pour cet exercice */
  maxWeight: number;
  /** Reps réalisées sur la série au poids max */
  repsAtMaxWeight: number;
}
```

### Calculs côté API

Les calculs se font côté API (pas frontend) pour :

- Éviter de transférer toutes les séries brutes au client
- Centraliser la logique de calcul
- Permettre de cacher/optimiser plus tard

**Query Prisma** : Joindre `WorkoutSession` → `SessionExercise` → `SessionSet` filtré par :

- `session.userId` = utilisateur courant
- `session.status` = `completed`
- `sessionExercise.status` = `completed` (exclure skipped/substituted)
- `sessionSet.actualReps IS NOT NULL AND sessionSet.actualWeight IS NOT NULL`

### Calculs côté Frontend

À partir des données `ExerciseSessionData[]` retournées par l'API :

1. **Filtrage par période** : filtrer `sessions` par `completedAt` selon la période sélectionnée
2. **Données graphique** : mapper `sessions` → points `{ date, value }` selon la métrique (bestE1RM ou totalVolume)
3. **TrendCard** : premier point et dernier point de la période → delta et %
4. **Fréquence** : `count = sessions.length`, `moisPeriode = durée période en mois`, `freq = count / moisPeriode`
5. **Poids max** : chercher dans les sessions filtrées celle avec le `maxWeight` le plus élevé

## Risks & Mitigations

| Risque                                             | Impact             | Mitigation                                                                                        |
| -------------------------------------------------- | ------------------ | ------------------------------------------------------------------------------------------------- |
| Performance si l'utilisateur a beaucoup de séances | Lenteur API        | Agrégation en une seule query Prisma optimisée, pas de N+1                                        |
| Exercices au poids de corps (pas de weight)        | Données manquantes | Exclure les séries sans actualWeight du calcul, afficher "Aucune donnée" si aucune série éligible |
| Formule E1RM peu précise à très hautes reps (>15)  | Valeur trompeuse   | Acceptable pour le MVP, la formule d'Epley est standard                                           |
| Beaucoup d'exercices pratiqués → grille longue     | UX surchargée      | Filtres par groupe musculaire + recherche inclus dans le scope                                    |
